HOW IT WORKS

Чӣ тавр APK сохтан мумкин?

Ин барнома файлҳои лоиҳаро омода мекунад. APK дар GitHub Actions сохта мешавад.

Асбобҳои ройгон

Нишона ва PNG, экрани оғоз, режими Desktop, фаъол нигоҳ доштани экран, ворид кардани папкаи сайт, пешнамоиш, санҷиши роҳҳои CSS/JS/расмҳо, хориҷ кардани файлҳои нолозим ва ZIP-и Android.

1. HTML ва файлҳоро интихоб кун

index.html, CSS, JavaScript, расмҳо ва дигар файлҳои сайтро илова кун. Агар сайт аз якчанд файл иборат бошад, папкаи пурраро интихоб кун.

2. Танзимотро пур кун

Номи барнома, Package ID, ранг, нишона, иҷозатҳои зарурӣ ва рафтори WebView-ро интихоб кун.

Пеш аз сохтмон

Дар қадами «Интегратсия» тугмаи «Санҷидани сайт ва файлҳо»-ро пахш кун. Барнома саҳифаи оғоз, истинодҳои маҳаллӣ, файлҳои гумшуда ва ҳаҷми умумиро месанҷад. Ин санҷиш хатогиҳои маъмулро меёбад, аммо ҷойгузини санҷиши APK-и воқеӣ нест.

3. APK-ро бе GitHub дар телефон соз

Дар қадами охир суроғаи HTTPS-и APK-серверро ворид кун ва «СОХТАНИ APK»-ро пахш намо. Сервер файлҳои сайтро қабул карда, APK месозад ва мустақим бармегардонад. Барои кори воқеӣ сервер бояд пешакӣ дар VPS/Docker ҷойгир шуда бошад.

4. APK-и тайёрро насб кун

Пас аз сохтмон APK дар app/build/outputs/apk/debug/app-debug.apk пайдо мешавад. Тугмаи Install-и IDE-ро қабул кун ё APK-ро аз ҳамин ҷузвдон кушо. Ин Debug APK барои санҷиш аст; барои Google Play имзои Release лозим мешавад.

5. Чӣ тавр барномаро ба Google Play гузорам?

Барои нашри оммавӣ ҳисоби Google Play Console лозим аст. Сабти номи таҳиягар одатан 25 доллари ИМА — як маротиба аст; соҳиби ҳисоб бояд ҳадди ақал 18-сола бошад ва санҷиши шахсиятро гузарад.

  1. Ба Play Console даро ва ҳисоби Developer соз.
  2. Create app-ро пахш кун; ном, забон, App/Game, Free/Paid ва Package ID-ро ворид кун. Package ID бояд беназир бошад ва баъд аз нашр иваз намешавад.
  3. Маълумоти саҳифаи мағоза пур кун: тавсиф, нишона, скриншотҳо, категория, email ва сиёсати махфият. Саволҳои App content, Data safety, Ads ва Content rating-ро рост пур кун.
  4. Барои нашри нав одатан файли Android App Bundle (.aab) лозим аст, на Debug APK. Release бояд бо калиди upload имзо шавад; Play App Signing-ро фаъол кун. Калиди махфиро ба касе нафирист ва дар GitHub ҳамчун матни оддӣ нагузор.
  5. Аввал Internal testing ё Closed testing-ро истифода кун. Агар ҳисоби шахсии ту баъд аз 13 ноябри 2023 сохта шуда бошад, барои дархости Production одатан ҳадди ақал 12 tester бояд 14 рӯзи пайваста дар Closed test иштирок кунанд.
  6. Пас аз пур кардани ҳамаи талабот, Production → Create new release-ро интихоб кун, AAB-ро бор кун, тафсилотро санҷ ва барои баррасии Google фирист.

Муҳим: HASANEX 14.1 метавонад тавассути APK-сервери шумо Debug APK созад. Барои ин сервер бояд алоҳида ҷойгир ва ба барнома пайваст карда шавад. Барои Google Play сохтани Release/AAB ва имзои бехатар ҳанӯз лозим аст.

1. Выберите HTML и файлы

Добавьте index.html, CSS, JavaScript, изображения и другие файлы сайта. Если сайт состоит из нескольких файлов, выберите всю папку.

2. Заполните настройки

Укажите название приложения, Package ID, цвет, иконку, необходимые разрешения и поведение WebView.

Перед сборкой

На шаге «Интеграция» нажмите «Проверить сайт и файлы». Приложение проверит стартовую страницу, локальные ссылки, отсутствующие файлы и общий размер. Проверка помогает найти распространённые ошибки, но не заменяет тестирование готового APK.

3. Соберите APK на телефоне без GitHub

На последнем шаге укажите HTTPS-адрес APK-сервера и нажмите «СОЗДАТЬ APK». Сервер получит файлы сайта, соберёт APK и вернёт его напрямую. Для работы сервер нужно заранее развернуть на VPS/Docker.

4. Установите готовый APK

После сборки APK появится в app/build/outputs/apk/debug/app-debug.apk. Примите предложение Install в IDE или откройте APK из этой папки. Это Debug APK для тестирования; для Google Play нужна Release-подпись.

5. Как опубликовать приложение в Google Play?

Для публичной публикации нужен аккаунт Google Play Console. Регистрация разработчика обычно стоит 25 долларов США один раз; владельцу аккаунта должно быть не менее 18 лет, также требуется проверка личности.

  1. Откройте Play Console и зарегистрируйте аккаунт разработчика.
  2. Нажмите Create app; укажите название, язык, тип App/Game, Free/Paid и Package ID. Package ID должен быть уникальным и не меняется после публикации.
  3. Заполните страницу магазина: описание, иконку, скриншоты, категорию, email и политику конфиденциальности. Правдиво заполните разделы App content, Data safety, Ads и Content rating.
  4. Для новой публикации обычно нужен Android App Bundle (.aab), а не Debug APK. Release подписывается upload-ключом; включите Play App Signing. Не передавайте секретный ключ другим и не храните его в открытом виде на GitHub.
  5. Сначала используйте Internal testing или Closed testing. Если личный аккаунт создан после 13 ноября 2023 года, для запроса Production обычно нужны минимум 12 тестировщиков, участвующих в закрытом тесте непрерывно 14 дней.
  6. После выполнения требований выберите Production → Create new release, загрузите AAB, проверьте данные и отправьте приложение Google на проверку.

Важно: HASANEX 14.1 может собирать Debug APK через ваш APK-сервер. Сервер нужно отдельно развернуть и подключить к приложению. Для Google Play по-прежнему нужны Release/AAB и безопасная подпись.

5. How do I publish my app on Google Play?

Public publishing requires a Google Play Console developer account. Registration is usually a one-time US$25 fee; the account owner must be at least 18 and complete identity verification.

  1. Open Play Console and register a developer account.
  2. Choose Create app; enter the app name, default language, App/Game type, Free/Paid status, and Package ID. The Package ID must be unique and cannot be changed after publication.
  3. Complete the store listing: description, icon, screenshots, category, contact email, and privacy policy. Answer App content, Data safety, Ads, and Content rating questions accurately.
  4. New app releases generally require an Android App Bundle (.aab), not a Debug APK. Sign the release with an upload key and enable Play App Signing. Never share your private key or store it as plain text in GitHub.
  5. Start with Internal testing or Closed testing. If your personal developer account was created after November 13, 2023, you generally need at least 12 testers opted into a closed test continuously for 14 days before requesting Production access.
  6. When all requirements are complete, choose Production → Create new release, upload the AAB, review the details, and submit the app to Google for review.

Important: HASANEX 14.1 can build a Debug APK through your APK server. The server must be deployed separately and connected to the app. Google Play still requires a Release/AAB build and secure signing.
